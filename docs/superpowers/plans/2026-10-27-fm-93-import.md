# FM-93: сохранение импортированных операций

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать атомарный импорт CSV/XLSX по FM-91.
**Architecture:** import_export координирует чтение, проверку категорий и одну единицу работы; transaction предоставляет публичные агрегат, репозиторий и UoW. category предоставляет чтение принадлежащих пользователю категорий под блокировками. Парсер сохраняет прежний публичный интерфейс, дополнительный результат разбора позволяет объединить ошибки полей и категорий.
**Tech Stack:** FastAPI, SQLAlchemy, asyncpg, PostgreSQL, pytest; python-multipart для multipart.
**Spec:** PPPoE15/fm-auto-dev origin/master:contracts/import-export.md и transaction.openapi.yaml, задача #93; зависимость #92 выполнена.

## Global Constraints

- Одна БД-транзакция; все операции или ни одной; дубликаты сохраняются.
- Четыре сочетания income/outcome × csv/xlsx, даты в полночь, суммы целые 1–1000000000.
- Чужие категории не видны; strip имён, точное сравнение, неоднозначность — ошибка.
- Файл 5 МиБ, multipart 6 МиБ, 10000 строк, 100 ошибок, 100000 операций пользователя.
- Импорты между модулями только через публичные __init__.py; docstring на русском.
- Проверки перед каждым коммитом: ruff check, ruff format --check, mypy, полная pytest с Postgres.

## Review Focus

- Конкурентные переименование, смена типа, удаление и обычная вставка не нарушают результат и квоту.
- Неизвестный исход COMMIT не выдаётся за успешный rollback.
- Ошибки категорий смешиваются с ошибками полей в порядке строк и колонок, максимум 100.
- Chunked-загрузка и ложный Content-Length не обходят лимит.
- Сбой последней записи откатывает весь пакет, включая финансовые итоги.
