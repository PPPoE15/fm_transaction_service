## Решения

Новый модуль хранит category_name_snapshot для completed; у pending имя читается актуально.
FK факта ON DELETE SET NULL и DB-триггер повышения версии обеспечат удаление любым существующим маршрутом, включая batch-delete.
Категории не импортируют planning; наличие планов проверяется через ORM relationship по имени.
Подтверждение и GET факта остаются FM-108; в FM-107 completed проверяется на подготовленных данных.

По правке пользователя CHECK-ограничения бизнес-правил удалены из ORM и миграции; валидация остаётся в приложении.

ORM-модель и таблица названы `PlannedTransaction` / `planned_transactions` по аналогии с фактическими транзакциями. API сохраняет адреса FM-106.
