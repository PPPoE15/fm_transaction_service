# FM-33 — индекс и ограничение фактов бюджета

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ускорить чтение операций пользователя и не агрегировать будущие месяцы бюджета.
**Architecture:** Составной неуникальный B-tree индекс объявлен в ORM и Alembic. Запрос отчёта получает верхнюю календарную границу; будущий год возвращает пустые факты без чтения transactions. Контракт ответа и доменные расчёты остаются прежними.
**Tech Stack:** Python, SQLAlchemy, Alembic, PostgreSQL 16, pytest/testcontainers.
**Spec:** PPPoE15/fm-auto-dev#33, зависимость #27 закрыта; база c229eca238fdae9ddad2713ac8d653adfb322cca.

## Ограничения
- Индекс ровно (user_uid, transaction_date); API не меняется.
- Русские docstring для новых функций, методов и тестов.
- Работать только в выделенном worktree; существующие локальные данные не затрагивать.
- Перед коммитом Ruff check/format, Mypy и полный pytest.

## Review Focus
- Январь/декабрь, прошлый/будущий год и 2099: верхняя граница без ошибок перехода года.
- Будущие дни текущего месяца должны учитываться, как раньше.
- Фильтры владельца/типа и BIGINT-суммы сохраняются.
- Upgrade/downgrade не удаляют данные; индекс совпадает с ORM/autogenerate.
- План EXPLAIN получен с обычными настройками planner и несколькими пользователями, без принудительного enable_seqscan=off.

## Решения
- Выполнение в текущем чате, один независимый ревьюер после CI, как в предыдущей работе пользователя.
- Обычный транзакционный CREATE INDEX согласован с существующей Alembic-цепочкой; возможность блокировки записей во время построения указать в PR/документации. Данные стенда не мигрировать автоматически.
